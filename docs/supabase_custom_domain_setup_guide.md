# Инструкция по настройке Custom Domain для Supabase (MagicMusic CRM)

Данная настройка нужна, чтобы приложение обращалось к Supabase через домен школы, а не через стандартный `*.supabase.co`. Это может улучшить доступность в сетях, где стандартный домен Supabase фильтруется, но не является полной заменой прокси или переносу backend: трафик все равно идет в инфраструктуру Supabase.

---

## 1. Задача
Настроить поддомен `api.magic-music.org` так, чтобы он указывал на инфраструктуру Supabase. Приложение использует этот домен для Auth, REST, Storage, Realtime и Edge Functions.

## 2. Действия со стороны Администратора домена (DNS)
После активации функции в панели управления Supabase, необходимо будет добавить 2-3 записи в DNS-зону домена `magic-music.org`.

### Текущая конфигурация

| Тип записи | Имя (Host) | Значение (Value/Points to) | Примечание |
| :--- | :--- | :--- | :--- |
| **CNAME** | `api` | `xblpnywnlhfgofskbdxb.supabase.co` | Основной шлюз Supabase |
| **TXT** | `_supabase.api` | `supabase-verification=xxxx-yyyy-zzzz` | Верификация владения доменом |

### Важное примечание для Cloudflare
Если домен `magic-music.org` обслуживается через Cloudflare, для данных записей **ОБЯЗАТЕЛЬНО** должен быть выбран режим **"DNS Only"** (серое облако). Режим "Proxied" (оранжевое облако) может конфликтовать с SSL-сертификатами, которые Supabase выпускает автоматически.

---

## 3. Порядок действий

1.  **Согласование**: Администратор подтверждает возможность создания поддомена.
2.  **Активация**: Разработчик приложения активирует функцию Custom Domain в Supabase.
3.  **Передача данных**: Разработчик отправляет администратору финальные значения `Value` и `Token`.
4.  **Обновление DNS**: Администратор вносит записи. Время распространения DNS обычно составляет от 15 минут до пары часов.
5.  **Верификация**: Supabase автоматически проверяет записи и выпускает SSL-сертификат.
6.  **Запуск**: Разработчик переключает приложение на `https://api.magic-music.org`.

## 4. Ограничения

- Если мобильный оператор блокирует маршрут до инфраструктуры Supabase/Cloudflare, один только CNAME может не помочь.
- В базе нельзя хранить абсолютные Storage URL на `*.supabase.co`. Для вложений и аватаров используйте `storage://bucket/path`, чтобы приложение строило URL через текущий Supabase host.
- После смены домена нужно мигрировать старые `avatar_url` и `attachment_url`, иначе часть картинок продолжит открываться через старый host.
