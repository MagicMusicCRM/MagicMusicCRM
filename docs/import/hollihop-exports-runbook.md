# Импорт выгрузок HolliHop — как пользоваться

Импортёр: `server/src/migration/import-hollihop-exports.ts`
Команда: `npm run hollihop:import-exports` (из `server/`)

## Зачем файлы, а не API

Комментариев, задач и истории **в API HolliHop нет** — методы `GetTasks`,
`GetComments`, `GetHistory` отвечают 404 (проверено 16.07.2026 боевым ключом,
подробности в [hollihop_api_probe_2026-07-16.md](hollihop_api_probe_2026-07-16.md)).
Единственный источник — выгрузка из интерфейса HolliHop.

Именно так в систему и попали 16656 комментариев и 514 задач: их писал файловый
импортёр, а не API.

## Что выгрузить

Сложите JSON-файлы (XLSX/CSV → JSON) в одну папку. Любого отсутствующего файла
импортёр просто не заметит — можно возить по частям.

| Файл | Корневой ключ | Колонки, которые читаются |
|---|---|---|
| `tasks.json` | `Tasks` | `Клиент`, `Описание`, `Дата выполнения`, `Ответственный`, `Моб. телефон`/`Телефон`, *(опц.)* `ID клиента`, `Статус`, `Дата завершения` |
| `task-history.json` | `History` | всё из `tasks.json` (чтобы найти задачу) + `Дата изменения`, `Поле`, `Было`, `Стало`, `Автор` |
| `students.json` | `Students` | `Фамилия`, `Имя`, `Описание`, телефон, *(опц.)* `ID клиента`, `Дата` |
| `leads.json` | `Leads` | `ФИО`, `Комментарий`, `Пользовательские поля`, телефон, *(опц.)* `ID клиента`, `Дата` |

**Выгружайте `ID клиента`, если такая колонка есть.** Тогда сопоставление идёт по
внешнему id — точно. Без него остаётся телефон, а это ровно тот механизм,
который в прошлый раз терял записи (у кого телефон не распознался — тот
пропал молча).

## Запуск

Сначала **всегда** dry-run (по умолчанию). Он ходит в БД только на чтение и
считает реальные совпадения:

```bash
cd server
HOLLIHOP_EXPORTS_DIR=/path/to/json npm run hollihop:import-exports
```

Отчёт по каждой секции:

```
tasks: 514 row(s) in source
  matched:   498 (by id 480, by phone 18)
  unmatched: 16 (no usable phone 4, no such record 12)
  written:   0 (dry run — nothing written)

⚠️  3 responsible name(s) had no matching user — those tasks land with no assignee:
     Иванов И.И.
     ...
```

Записать:

```bash
HOLLIHOP_EXPORTS_DIR=/path/to/json HOLLIHOP_EXPORT_IMPORT_MODE=apply \
  npm run hollihop:import-exports
```

Нужна `MIGRATION_DATABASE_URL` или `DATABASE_URL`.

## Что гарантируется

- **Повторный запуск безопасен.** Id каждой строки выводится детерминированно из
  её содержимого, вставка идёт `on conflict (id) do nothing`. Прогнать дважды =
  прогнать один раз. Схема id совпадает с прежним импортом, поэтому уже
  залитые 514 задач не задвоятся.
- **Всё или ничего.** `apply` работает в одной транзакции.
- **История задач — с исходными датами**, а не датой импорта (`changed_at` из
  колонки `Дата изменения`), и помечается `source='hollihop'` — чтобы
  переимпорт мог заменить свои строки, не трогая то, что делали руками.
- **Полнота проверяема.** Отчёт показывает, сколько строк в источнике, сколько
  сопоставлено и **почему** остальные нет. Без этого «добились всех данных» —
  не критерий.

## Известные ограничения

- **Ответственный.** У всех 514 ранее импортированных задач `assigned_to = NULL`:
  колонка `Ответственный` содержит «[Для всех]», а настоящее имя лежит внутри
  текста — «(поставил Иванов И.И. - 12.03.2026)». Импортёр теперь достаёт имя и
  оттуда, но сопоставить его с пользователем можно, только если такой сотрудник
  заведён в системе. Кого не нашли — печатается списком в конце отчёта, а не
  проглатывается.
- **Поурочной оплаты педагогам нет ни в API, ни в этих выгрузках.** Если она
  нужна — требуется отдельная выгрузка с суммами, и её формат надо будет
  разобрать.
- Импортёр **дообогащает** существующие записи. Учеников и лидов он не создаёт:
  строка, которой не нашлось владельца, попадает в `unmatched` и пропускается.
