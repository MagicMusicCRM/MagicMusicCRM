# Чек-лист данных: что обязано быть в базе

Назначение: пересобрать базу с нуля из выгрузок HolliHop и **проверить**, что в
ней есть всё нужное. Без этого «добились всех данных» — не критерий, а надежда.

Заполняется на **локальной** базе, потом теми же запросами сверяется прод.

Легенда: `[x]` сверено · `[ ]` не сверено · ⚠️ известное расхождение с
обоснованием · ❌ источника нет

❌ **Привязки платежа к занятию в источнике НЕТ.** `GetPayments` даёт `ClientId`,

импортированных, и это норма (см. миграцию `0065`).

## 5. Задачи и история ← главное

Источник — **«Коммуникации»**, а не «Задачи»: там все задачи за всё время.

```

Статус "Закрыта" (установил Мазалова А. Ю.) - 16.06 19:42 ← событие
```

⚠️ **5.6 — реальный пробел, и он не тот, о котором все писали.** Полгода в
доках, в коде и в тестах стояло «у всех 514 задач `assigned_to = NULL`».
Измерено на проде 17.07 — **неправда**: исполнитель есть у **513 из 514**, и
разложен по настоящим менеджерам (Мазалова 194, Богатырёва 151, Крошкин 111,

Пустует **соседнее поле**: `created_by` — **0 из 514**. Кто поставил задачу, не
знает никто. Оно есть в тексте и достаётся `parseTaskDescription`. Отсюда и 5.9:
раз уж утверждение про исполнителя однажды оказалось выдуманным, пусть его
проверяет запрос, а не память.

**Не сопоставится ~676 (5%)**: 160 имя даёт несколько лидов · 489 имени нет
среди лидов (много с отчеством) · 25 id нет в базе · 2 id пересёкся с лидом.
Каждая причина обязана быть в отчёте, а не проглочена.

**Формы записи — поддержать обе:**
- `(поставил X - 21.06)` — 7 208 · `(поставил X - 09.07.25)` — 5 062
- `Статус "Закрыта" (установил Y) - 21.06 14:14` — 11 845 · `Статус "Закрыта" - 06.09.25 16:04` — **316, без автора**
- Единственный статус во всех 12 162 — `"Закрыта"`.

**Год восстановим:** у 5 062 явный; у остальных из даты строки — проверено, у
**всех 6 688** закрытых «поставил» строго раньше закрытия.

## 7. Ручная сверка «Маг Анри» (лид `6045`)

Эталон от заказчика. После сборки обязано быть:

- [ ] Лид найден: `first_name='Анри'`, `last_name='Маг'`, `hollihopId=6045`, PK `ab858641-a532-4497-a22d-b49436e50a43`
- [ ] **Комментарий карточки** — текст про «мужчина без особого опыта… меломан… не хочет тратить больше 2500»
- [ ] **1 открытая задача**, срок `11.08.2027`: «инфо задача: если будут новые педагоги по вокалу…», автор Мазалова А. Ю.
- [ ] **4 закрытые задачи** с историей: 21.06 (закрыла Мазалова), 18.06 (закрыла Богатырёва), 17.06 (Мазалова), 16.06 (Мазалова)
- [ ] В тексте задач **нет** служебных строк «(поставил…)» и «Статус "…"» — они разобраны в поля
- [ ] Карточка открывается **одна**, не двоится

```sql
select t.status, t.due_at::date, left(t.title,50), u.email as автор
from app.tasks t
join app.leads l on l.id = t.entity_id and t.entity_type='lead'
left join app.users u on u.id = t.created_by
where l.custom_data->>'hollihopId' = '6045' and t.deleted_at is null
order by t.due_at desc nulls last;
```
