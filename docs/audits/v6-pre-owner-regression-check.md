# Пред-UAT проверка: вход, поиск, расписание, аналитика и настройки

**Дата:** 2026-08-06
**Кандидат для проверки владельцем:** `1.2.2+155`
**Итог:** ENGINEERING PASS; подпись OWNER UAT остаётся за владельцем

## Что проверено и исправлено

### Сессия после обновления и повторный вход

Сохранение действующей сессии после обновления оставлено намеренно: обновление
приложения не должно само разлогинивать пользователя. Проверен опасный сценарий:
холодный старт с сохранённой сессией Client → выход → вход Director → выход →
повторный вход Client. Windows Credential Manager и Android encrypted storage
прошли этот сценарий на production API. Поля формы входа при ошибке не очищаются.

### Поиск лидов и учеников

- Ученики фильтруются локально: ввод символа не вызывает API-запрос и не
  перемонтирует доску.
- Лиды мгновенно фильтруют уже загруженные карточки, а серверный поиск запускается
  один раз после debounce. Предыдущая доска теперь остаётся на экране даже при
  смене Riverpod family-key; полноэкранный skeleton во время набора исключён.
- Регрессионные тесты проверяют накопление текста по одному символу, сохранение
  focus и число запросов.

### Поиск занятий

- Поиск больше не переводит пользователя принудительно в День и не исчезает
  после краткого glow.
- В режимах День и Неделя совпавшие занятия зелёные, остальные серые; первое
  совпадение дополнительно получает золотой акцент на четыре секунды.
- В режиме Месяц зелёными отмечаются только дни с совпадением, остальные дни
  нейтрально-серые.
- Активный запрос виден отдельным chip с понятной легендой и кнопкой очистки;
  состояние переживает восстановление workspace.
- По ФИО используется существующий actor-scoped `/crm/clients/search`, затем
  точечная матрица найденного Lead/Student. Это закрывает пропуски после общего
  лимита матрицы: production-probe дал `521` занятие в месяце, `500` в общей
  выборке и `8` точечных занятий клиента; поздняя запись найдена.
- Backend-контракты и server-код для этой правки не менялись.

### Аналитика

Раздел оставлен с двумя ясными рабочими окнами: **Обзор** и **Журналы**. Дубликат
«Каталог» удалён из аналитики; каталог абонементов имеет один дом —
**Настройки → Продажи и оплаты**. Общие период/филиал, независимые состояния
секций, drill-down и role-safe school finance сохранены.

### Настройки и «Справочники»

Проверен единый workspace из шести бизнес-разделов: Организация, Расписание,
CRM, Продажи и оплаты, Пользователи и доступы, Данные и обслуживание.

Перед финальной сборкой в production workspace подключены ранее изолированные
формы создания сотрудника, преподавателя и группы. Права проверяются теми же
capability snapshot и backend-командами; Управляющий не может назначить роль
Управляющего/Директора, Директор — только роли ниже себя.

«Справочники» не являются отдельным пользовательским модулем. Это небольшие
переиспользуемые наборы вариантов для custom select-полей: например, один список
«Направления» можно использовать и у лида, и у ученика, меняя его в одном месте.
Функция имеет смысл и уже встроена в конфигуратор, но техническое название было
непонятным. В UI она переименована в **«Варианты для полей»** и снабжена примером.
Новый универсальный reference-data framework не создавался.

После уточнения владельца это единственное пользовательское место редактирования
значений select/radio/multi-select/checkbox-group полей. В редакторе поля остался
только обязательный выбор набора и shortcut «Создать новый набор». Старые
inline-списки при открытии школьной конфигурации преобразуются в именованные
наборы с сохранением labels и текущих значений; конфигурация помечается как
черновик до обычного preview/publish.
