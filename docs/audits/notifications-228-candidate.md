## Подтверждённые причины и границы

- В production `app.notification_preferences` имеет 0 строк. Код `notifyInboundLead` выбирает получателей только из включённых строк, поэтому при текущих данных адресатов нет. Почему строки исчезли, не установлено.
- Desktop toast прежде слушал любой `lead.created`, поэтому реагировал и на ручное создание. В новой версии он слушает адресное событие созданного уведомления `new_lead`.
- Outbox фильтровал поле `affectedUserIds`; создание общей задачи не сохраняло получателей в payload. Оба разрыва исправлены. Заодно это восстанавливает уже предусмотренную адресацию других событий, использующих то же поле.
- В production зарегистрировано одно активное FCM устройство у `system_admin`; у client, teacher, admin, manager и director устройств нет. Ни сборка, ни unit тест не доказывают показ push на их телефонах. Проверка требует входа этих ролей в приложение и разрешения уведомлений.
- По решению владельца переключатели `task_reminder_*` убраны из UI и допустимых параметров API: канонические напоминания общих задач задают время и канал на самой задаче, а прежние ролевые переключатели на них не влияли. Исторические строки настроек не удаляются. Миграция 0161 восстанавливает только действующие настройки `new_lead`.
