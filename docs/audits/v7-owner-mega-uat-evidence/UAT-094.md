# UAT-094 — отмена занятия всеми применимыми типами

Дата: 2026-08-12
Статус матрицы: `PARTIAL` — локальная реализация и техническая проверка PASS,
production owner UI/API/DB evidence ещё не получены.

## Канонический контракт

Отмена выполняется только через общий `LessonTransitionService` и одну
`LessonDecisionFlow`: обязательны причина, финансовое решение, signed preview,
явное подтверждение, `expectedVersion` и idempotency identity. Preview и commit
повторно читают Lesson и settlement coverage в PostgreSQL transaction; commit
сверяет подписанный fingerprint и создаёт одну immutable transition history.

Из семи базовых типов расчёта контекст `cancel` разрешён ровно для пяти:

| Тип | Часы | Резерв | Остаток абонемента 1 ч | Teacher pay |
|---|---:|---|---:|---:|
| Бесплатное занятие | `0.00` | `released` | `1.00` | `700,00 ₽` |
| Оплачиваемый пропуск | `1.00` | `consumed` | `0.00` | `700,00 ₽` |
| Частично оплачиваемый пропуск | `0.50` | `consumed` | `0.50` | `700,00 ₽` |
| Неоплачиваемый пропуск | `0.00` | `released` | `1.00` | `700,00 ₽` |
| Занятие со штрафом | `1.00` | `consumed` | `0.00` | `700,00 ₽` |

Teacher pay выбирается независимо; в матрице использована полная стандартная
ставка frozen snapshot. Обычное и частично оплачиваемое занятие доступны только
в контексте `settle`: попытка передать их напрямую в cancel preview получает
`422 SETTLEMENT_TYPE_NOT_ALLOWED` и не создаёт ни одного факта.

## UI и stale-version

До исправления `STALE_LESSON_VERSION` оставлял форму на кнопке повторного
commit с уже недействительным preview token и idempotency identity. Общий
контроллер теперь:

- распознаёт `STALE_LESSON_VERSION` и `LESSON_TRANSITION_PREVIEW_STALE`;
- сохраняет причину и выбранные финансовые параметры;
- принимает `currentVersion` во внутреннее состояние, не изменяя входную Map;
- сбрасывает только недействительные preview/identity;
- объясняет конкурентное изменение по-русски и возвращает кнопку
  `Рассчитать`.

Обычная сетевая ошибка по-прежнему сохраняет тот же preview и idempotency key
для безопасного retry.

## PostgreSQL до/после

Табличный integration test для каждого из пяти типов подтвердил:

- Lesson: `scheduled v1 → cancelled v2`;
- preview и persisted fact имеют одинаковые key, label, color, hours и
  configuration revision;
- reservation `consumed/released` и доступный остаток совпадают с расчётом;
- reason code/text и полное financial decision записаны в transition;
- ровно по одному client fact, teacher fact, transition, audit, outbox и
  completed idempotency record;
- повтор той же команды возвращает `replayed=true` с теми же fact/transition
  IDs и не создаёт дублей.

Тестовый fixture cleanup удаляет все абонементы созданного fixture-ученика.
Gate обнаружил прежний узкий cleanup после добавления пяти тестовых
абонементов; 11 orphan fixture-строк были удалены только из локальной тестовой
БД, после повторного targeted run drift равен `0`.
