# UAT-140–UAT-144 — ролевые functional tours

Статус: **PARTIAL**. Сквозные ролевые туры подтверждены на локальном кандидате;
production не изменялся, owner production-UAT ещё не выполнялся.

## UAT-140 — Client

Один тест проходит реальный `ClientDashboardScreen` через все четыре раздела:

- `Чат`: доступен собственный чат с администрацией;
- `Занятия`: видны предстоящее занятие, история и домашнее задание;
- `Абонемент`: видны пакет, часы, paid/debt/pending/overpayment и ближайший
  платёж, затем actor-scoped история оплат;
- `Профиль`: видны собственные данные и роль `Клиент`.

Тот же тест явно проверяет, что Client не отправляет запросы к
`/crm/students/:id`, global payments/expenses, school-finance, package catalog,
internal note и operational history.

Результаты:

- Android 15 / API 35: `1/1 PASS`;
- Windows runner с мобильным viewport `412×915`: Client часть `1/1 PASS`;
- targeted analyze: `PASS`.

UI evidence мобильной раскладки:

- `client-android-persona-subscription.png`;
- `client-android-persona-profile.png`.

Кадры записаны детерминированным Windows runner в том же мобильном viewport;
Android API 35 подтверждён отдельным исполнением того же теста.

## UAT-141 — Teacher

Тест монтирует настоящий `TeacherDashboardScreen` в mobile viewport `412×915`
и проходит доступные преподавателю разделы:

- `Чат`;
- `Расписание` с assigned-only календарём без создания занятия;
- `Ученики` с назначенным учеником.

Во время первого прогона тест обнаружил реальный дефект: компактный
`ProductionWorkspaceHost` не рисовал общую навигацию, а вложенный
`MessengerScreen` при `workspaceOwned=true` также её отключал. В итоге Teacher
на телефоне оставался в чате. Общая мобильная оболочка исправлена, добавлен
регрессионный widget-тест переключения всех трёх поверхностей.

API trace содержит только assigned teacher/schedule/student reads, не содержит
commerce, contacts или internal-note запросов и не выполняет бизнес-мутаций.

Результаты: Android 15/API 35 `1/1`; Windows mobile viewport в общем role
runner `1/1`.

UI evidence:

- `teacher-android-persona-schedule.png`;
- `teacher-android-persona-students.png`.

## UAT-142 — Admin

Настоящий `AdminDashboardScreen` на Windows `1280×900` показывает только
операционные разделы `Чат`, `Расписание`, `Клиенты`, `Задачи`. Тест проходит
каждый раздел, подтверждает default task scope `Мои` + `Сегодня` и отсутствие
Overview, Analytics, Settings и school-wide Finance. API trace не содержит
school-finance/expenses; штатные `/crm/sections/seen` считаются read-state, а
не бизнес-мутацией.

UI evidence: `admin-windows-persona-tasks.png`.

## UAT-143 — Manager

Тест монтирует настоящий `ManagerDashboardScreen` и production workspace на
Windows `1280×900`, после чего открывает:

- `Обзор` без общешкольных денежных KPI;
- `Расписание`;
- `Клиенты` с Lead/Student досками;
- `Задачи`;
- `Аналитика` без school-finance и Finance XLSX;

  создания.

Записанный API trace подтверждает отсутствие `/analytics/v4/school-finance`,
global payments/expenses и mutation package/access endpoint. Windows device
результат: `1/1 PASS` внутри общего файла `2/2`.

UI evidence:

- `manager-windows-persona-analytics.png`;
- `manager-windows-persona-settings.png`.
