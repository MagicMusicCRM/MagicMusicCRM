## Пользовательский контракт

- Для задачи на весь день дата по умолчанию — следующий календарный день, без
  случайно сохранённого времени создания формы.
- Для интервальной задачи окончание обязательно позже начала; некорректный
  интервал виден пользователю и не может быть отправлен.
- Включённое in-app напоминание всегда показывает и позволяет изменить точные
  дату и время. По умолчанию это `09:00` даты all-day задачи либо один час до
  начала интервальной задачи.
- Изменение in-app напоминания не удаляет уже сохранённые email/push каналы,
  которые текущая форма не редактирует.
- Person, Branch и School audience используют один preview. Backend сохраняет
  ровно тот набор уникальных получателей, который показан перед созданием.
- Уведомление содержит `entityType=task` и точный `entityId`, поэтому открывает
  нужную задачу. Прочитанное состояние сохраняется после пересоздания клиента.

## PostgreSQL и отказоустойчивость

Table-driven интеграция создаёт от Manager три реальные задачи: person
all-day, branch interval и school interval. Для каждой строки доказаны exact
`recipientSummary`, сохранённые audience/reminder и равенство preview числу
уникальных `reminderRecipients` в БД.

Отдельный сценарий имитирует сбой второго получателя после уже сохранённого
уведомления первого. Retry использует стабильный notification id для пары
`reminder + recipient`, завершает доставку двум получателям и оставляет ровно
два уведомления и две recipient-записи — без повторной email/push постановки.
После `markRead` новый экземпляр notification service возвращает ту же запись
прочитанной.

Актуальное имя runtime-флага — `TASK_REMINDERS_ENABLED`. Старое имя в
историческом v4-аудите исправлено; production-конфигурация в этой волне не
изменялась.
