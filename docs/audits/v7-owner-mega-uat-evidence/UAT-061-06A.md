# UAT-061–06A и UAT-131 — финансы клиента и безопасный Retry

Статус: **PARTIAL**. Техническая часть подтверждена на локальном кандидате.
Production не изменялся; для `PASS` всё ещё нужен owner UI/API/DB-проход на
production-reachable Release.

| UAT-131 | Сетевой сбой сохраняет черновик платежа и стабильную identity; issue/replace/cancel повторяют commit с тем же idempotency. `401` вызывает один общий refresh, параллельные запросы не создают refresh-loop, а повторный login не читает старую сессию. |

## Изменения кандидата

- Добавлены migration `0130_account_adjustment_reversal`, два capability-gated
  endpoint и signed preview token для сторно корректировки.
- Сторно выполняется через общий Platform Integrity path: expected version,
  idempotency, audit, outbox и append-only facts; destructive update исходной
  финансовой записи не используется.
- Commerce projection проецирует version корректировки, actual payment source
  и nullable technical-history поля; Flutter показывает действие сторно и
  обновляет ledger после commit.
- Package catalog получил active/archive filter, restore и branch label.
- Карточка абонемента получила точные paid/debt/pending/overpayment/next-payment
  показатели.
