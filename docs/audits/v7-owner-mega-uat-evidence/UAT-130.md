# UAT-130 — double-submit и идемпотентность команд

Статус: **PARTIAL**. Пять обязательных команд полностью доказаны на локальном
checkout; production owner UI/API/DB-повтор не выполнялся.

## Единый gate пяти команд

| Команда | Защита от повтора | Доказательство |
|---|---|---|
| Lead → Student | Одновременные команды под одним Lead lock создают один Student, один conversion link и возвращают `replayed=false/true` | `conversion-postgres.integration.spec.ts` |
| Actual payment | Два параллельных `record` с одной identity возвращают один Payment; изменённый fingerprint отклоняется; append-only update/delete запрещены | `subscription-issue-postgres.integration.spec.ts` |
| Subscription purchase | Повтор с тем же signed preview/idempotency identity возвращает тот же subscription и не дублирует ledger/audit/outbox | `subscription-issue-postgres.integration.spec.ts` |
| Shared task close | Два текущих получателя одновременно закрывают задачу; итог один, `task_closes/audit/outbox` имеют cardinality `1` | `shared-task-postgres.integration.spec.ts` |
| Lesson transition | Reschedule/cancel повторяет signed preview + expected version + identity и возвращает stable `replayed=true` без второго transition/fact | `reschedule-postgres.integration.spec.ts` |

Объединённый PostgreSQL запуск: `4/4` suites, `35/35` tests.

## UI-защита

- Payment и Subscription после сетевого сбоя сохраняют весь черновик и ту же
  `idempotencyKey/requestId` для явного Retry.
- Create Lesson блокирует второе нажатие, пока первая команда выполняется:
  `2` быстрых tap дают ровно `1` mutation.
- Lesson decision retry сохраняет reason/preview/identity; новый осознанный
  draft получает новую identity.
- Shared Task хранит identity до успешного close, отключает кнопку во время
  запроса и после ошибки предлагает явный Retry без закрытия карточки.

Targeted Flutter: payment/subscription/lesson `37/37`, task UI `17/17`, всего
`54/54`.

## Остаток до PASS

На production-reachable Release владелец должен повторить двойное нажатие и
сетевой replay для disposable данных, затем сверить UI-result, API response и
DB cardinality по каждой из пяти команд. Production в этой волне не изменялся.
