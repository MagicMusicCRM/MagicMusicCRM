# UAT-020–029 — локальный кандидат конфигурации CRM

Дата: `2026-08-12`
Среда: локальный Flutter/backend-кандидат, production не изменялся.

## Закрытые технические разрывы

- категории поддерживают создание, переименование, порядок, архив и
  восстановление; категория с активными полями не архивируется;
- редактор покрывает 16 типов полей, ширины `third/half/full` и размещения
  `create/edit/card/table`;
- одиночные и множественные варианты редактируются построчно со стабильными
  ключами, порядком и архивированием;
- существующая карточка Lead/Student читает и пишет тот же typed storage, что и
  формы создания; параллельный legacy-путь больше не используется карточкой;
- `card`-only поля отображаются без возможности изменения, ширины применяются
  адаптивно, `table`-поля приходят ограниченной проекцией и видны на досках
  Lead/Student;
- архивные typed-значения не попадают в активную проекцию, но сохраняются при
  последующих сохранениях карточки;
- `default_lesson_duration_minutes` реально задаёт начальную длительность новой
  формы занятия с учётом branch override;
- `payment_reminder_days` теперь имеет runtime consumer: effective school/
  Branch-значение задаёт окно до immutable installment, получателями становятся
  только активные Client app-аккаунты плательщика, а durable lease/retry marker
  и стабильный notification ID не допускают дубль при параллельном polling;
- draft/preview/publish/rollback, school/branch source map, 7 списаний, 5 правил
  оплаты и RBAC конфигурации покрыты существующим единым configuration runtime.
- Student board применяет опубликованные `allowedTransitions`: запрещённый drop
  не вызывает mutation, разрешённый PATCH после refetch переносит карточку и
  обновляет счётчики; backend повторяет проверку транзакционно, пишет одну
  status-history row и отклоняет запрещённый переход structured `422` без
  частичного состояния.
