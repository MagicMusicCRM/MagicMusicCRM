# UAT-115 — data quality и deletion request

Дата: `2026-08-12`
Статус: `PARTIAL`
Среда: локальный кандидат; production не изменялся

## Что закрыто локально

- Очередь phone review получила два явных решения: исправить до
  канонического RU-телефона или принять как есть. Причина обязательна;
  source entity и queue row изменяются в одной транзакции под row lock,
  audit не содержит raw phone. Миграция: `0129`.
- Deletion request создаётся без гонки за единственный active request.
  Client может отменить только `pending`; в `processing` отмена fail-closed.
- Admin/Director/system_admin может вести
  `pending → processing → completed/rejected`; Manager видит список read-only.
  Terminal transition требует причину, а completion в UI — отдельное
  подтверждение анонимизации.
- Completion в одной транзакции анонимизирует user/profile PII,
  удаляет identities, devices и auth/reset/OTP tokens, отзывает refresh sessions.
  Deletion request, consent, legal, financial, lesson, operational и audit-история
  сохраняются.

## Почему ещё не PASS

Production mutation/deploy не выполнялись. Реальный `magic1` не
использовался как target и не изменялся. Для `PASS` владелец должен
пройти оба phone-review исхода и полный deletion lifecycle на отдельном
disposable UAT-client с UI/API/DB evidence, не затрагивая owner-аккаунт.
