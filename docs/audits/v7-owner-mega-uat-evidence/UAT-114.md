# UAT-114 — расходы и finance RBAC

Статус: **PARTIAL**. Это локальное UI/API/PostgreSQL-доказательство текущего
checkout. Production не изменялся, поэтому owner-повтор остаётся обязательным.

## Что доказано

- Director открывает канонический маршрут `Аналитика → Журналы →
  Финансовые операции`, создаёт, изменяет и удаляет расход.
- Новый расход автоматически получает Branch из текущего фильтра; edit
  предзаполняет сумму, категорию и комментарий, а после mutation
  всегда выполняется readback с API.
- В ограниченной по высоте прокручиваемой истории доступны действия для всех
  `50` загруженных API-строк, а не только для трёх последних; widget-сценарий
  отдельно доходит до десятой записи и открывает её редактирование.
- Delete требует явного подтверждения и объясняет, что строка перестанет
  учитываться, но audit сохранится.
- Реальный PostgreSQL-сценарий провёл `1250 → 1750 → delete`: list total и
  school-finance `expensesMinor` стали `1750`/`175000`, после delete — `0`/`0`.
  Строка физически осталась с `deleted_at` и исправленной суммой; audit и
  realtime получили ровно `created/updated/deleted`.
- Manager получает backend `Forbidden` для list/create/update/delete, не видит
  финансовый журнал и не отправляет `/crm/expenses`.
