# UAT-110 — прямой чат и медиа

Дата: 2026-08-12
Статус матрицы: `PARTIAL` — инженерный контур локально закрыт; для итогового
`PASS` нужны owner UI/API/DB evidence на production candidate для
Client↔Admin и Teacher↔Manager.

## Пользовательский контракт

- Client общается со Staff через канонический чат `Администрация`; отдельный
  direct-чат с Client не создаётся. Teacher и Manager используют обычный
  direct-чат.
- Текст, изображение, файл и voice сохраняются одним message aggregate.
  Длительность voice является серверным полем и после повторного открытия
  остаётся доступна проигрывателю.
- Тип сообщения обязан соответствовать назначению и MIME загруженного файла.
  К сообщению можно прикрепить только собственный незавершённый upload из того
  же чата. Если commit сообщения падает, Flutter удаляет только что загруженный
  сиротский файл best-effort.
- Reply разрешён только на существующее неудалённое сообщение того же чата.
  Forward хранит ID исходного сообщения, а не пользователя, и допускается
  только из доступного отправителю чата. UI пересылает текст; привязанный к
  исходному чату private file не переиспользуется как чужое вложение.
- Собственный текст редактируется и удаляется; медиа удаляется soft-delete без
  нарушения payload constraint. Реакции, read receipt и pin сохраняются.
  В direct-чате pin доступен обоим активным участникам; управление составом
  Group по-прежнему остаётся привилегированным.

## Найденные и закрытые разрывы

1. Flutter держал длительность voice только в локальном map, поэтому после
   reload она исчезала. Поле теперь проходит DTO → PostgreSQL → mapper → UI.
2. Backend принимал несовместимые `messageType`, purpose и MIME и позволял
   участнику привязать upload другого участника. Добавлены fail-closed
   проверки типа, владельца и чата.
3. Не проверялись границы reply/forward; UI записывал в `forwarded_from_id`
   `sender_id`, хотя FK ожидает message ID. Контракт и UI исправлены.
4. Неудача message commit оставляла private upload сиротой. Добавлен rollback
   через File API.
5. Старый `message_payload_check` блокировал soft-delete image/file/voice,
   потому что после удаления payload намеренно пуст. Миграция `0125` сохраняет
   fail-closed payload для активных сообщений и допускает tombstone.
6. Teacher видел действие pin в direct-чате, но backend отвечал `403`. Права
   UI/API выровнены без расширения прав на Group или Administration.

- [`direct-chat-media.png`](direct-chat-media.png) — тёмный Windows экран

  восстановленная voice duration, forward и media tombstone.

  реальном PostgreSQL text/image/file/voice, edit, reaction, pin обоими
  участниками, read receipt и media delete. Там же доказаны owner isolation,
  cross-chat reply/forward rejection, отсутствие partial messages и FK на
  file object.
- DTO/service/migration tests покрывают bounded voice duration, MIME/purpose,
  owner binding и обратимость `0125`; Flutter service/widget tests покрывают
  request/readback, upload rollback и persisted duration UI.
