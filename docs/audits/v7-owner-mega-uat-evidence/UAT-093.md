# UAT-093 — два Manager одновременно бронируют один слот

Дата: 2026-08-12
Статус матрицы: `PARTIAL` — локальная реализация и техническая проверка PASS,
production owner UI/API/DB evidence ещё не получены.

## Проверенный контракт

Два независимых Manager-аккаунта с разными `actorKey`, idempotency key и
request ID одновременно отправили одинаковый полный draft разового занятия.
Оба запроса прошли через один `LessonCommandService.create`.

Commit берёт отсортированные transaction-scoped advisory locks по Branch,
Client, Room и Teacher, после чего повторно запускает канонический
`ScheduleConstraintEngine` уже внутри той же PostgreSQL transaction. Поэтому
первый commit становится winner, а второй после ожидания lock видит созданный
Lesson и получает authoritative `422 LESSON_CONSTRAINT_VIOLATIONS` с
`TEACHER_OVERLAP`, `CLIENT_OVERLAP` и `ROOM_OVERLAP`.

факта не остаётся.
