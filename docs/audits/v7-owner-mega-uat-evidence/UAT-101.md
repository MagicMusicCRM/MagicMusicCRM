# UAT-101 — скрытые и опубликованные преподавателю комментарии

Дата: 2026-08-12
Статус матрицы: `PARTIAL` — локальная реализация и техническая проверка PASS,
production owner UI/API/DB evidence ещё не получены.

## Ролевой контракт

- Admin, Manager, Director и system administrator видят служебные комментарии
  и могут явно включить или выключить доступ преподавателя.
- Назначенный Teacher получает только строки с
  `shared_with_teacher = true`; неназначенный Teacher получает `404` без
  подтверждения существования карточки.
- Client не получает ни `admin_comment`, ни `teacher_note`. Поток `progress`
  остаётся отдельной клиентской учебной записью и не смешивается со служебными
  комментариями.
- Переключение использует `expectedVersion`, request/idempotency identity,
  один audit и один outbox. Тело комментария отсутствует в outbox и audit-
  проекции.

PostgreSQL проверяет четыре разрешённые staff-роли, отказ Teacher/Client без
частичных записей, stale-version rollback, exact replay и фильтрацию Teacher/
Client.

## Windows UI

Тёмный Windows device прошёл один непрерывный сценарий:

1. Manager видит скрытый и уже опубликованный комментарии;
2. создаёт новый `admin_comment`, который помечен как видимый только админам;
3. публикует его преподавателю точным versioned PATCH;
4. Teacher открывает свою учебную карточку и видит только два опубликованных
   текста, без исходного скрытого служебного контекста.

Во время первой визуальной проверки найден реальный UI-дефект: refresh после
PATCH возвращал `Future` из callback `setState`, из-за чего успешная публикация
показывала техническую ошибку. Async-загрузка вынесена из callback, а
`setState` теперь только синхронно меняет `_future`. Device-тест отдельно
запрещает оба технических текста ошибки.
