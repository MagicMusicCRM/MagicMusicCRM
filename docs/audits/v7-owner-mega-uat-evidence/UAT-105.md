Дата: 2026-08-12

## Закрытый разрыв

Карточка уже читала immutable `app.audit_events`, но её allowlist и SQL-связи
не включали три обязательных семейства UAT:

- `crm.lead_converted`;
- `crm.comment_created` и `crm.comment_teacher_sharing_changed`;
- `workflow.shared_task_created/updated/closed`.

Теперь та же bounded keyset-история связывает conversion через Lead/Student
lineage, изменение видимости через `app.entity_comments`, а задачи — через
канонический `app.shared_tasks.linked_entity_type/id`. Отдельная timeline-
модель не создавалась.

Для действий без пользовательского поля причины API показывает безопасное
русское объяснение (`Конвертация лида завершена`, `Комментарий добавлен`,
`Задача создана/изменена/закрыта`). Переключение видимости дополнительно пишет
явный `reason_text`: опубликован или скрыт комментарий. Commerce и Lesson-
действия продолжают показывать точную введённую пользователем причину.

## Защита данных

История возвращает только action, безопасную причину/summary, автора и время.
PostgreSQL regression создаёт приватное тело комментария и доказывает, что оно
не появляется в JSON operational history. Teacher и Client по-прежнему
отсекаются до запроса истории; Flutter для этих ролей не монтирует скрытый
endpoint.
