# UAT-034 — сотрудники, роли и app users

Статус: **PARTIAL**. Локальная UI/API/DB negative matrix закрыта; production
owner Release-повтор ещё не выполнен.

## Единственная зона изменения роли

Роль доступа изменяется только через
`Настройки -> Пользователи и доступы -> Доступы`. Создание сотрудника не имеет
role picker и создаёт обычную карточку Admin; email/пароль необязательны и
задаются парой. В карточке существующего сотрудника роль отображается read-only
с подсказкой о переходе в «Доступы» — одинаково для Manager и Director.

## UI negative matrix

- Manager видит список пользователей, но не получает ни role selector, ни
  кнопку сохранения роли/override;
- Director видит нижестоящие роли и capability package, но не видит
  `system_admin`; смена требует причины и явного подтверждения сброса overrides;
- Director не может менять собственную роль;
- `system_admin` может назначать полный набор только через помеченную emergency
  surface;
- ответ `409` перечитывает серверную версию и не оставляет частичную
  optimistic role mutation.

## Backend hard invariants

`PUT /access/users/:id/role` повторно проверяет capability, иерархию ролей,
self-mutation, active subject, last active system admin, emergency surface,
expected version и подтверждение reset overrides. Успешная операция атомарно
обновляет роль/access version, синхронизирует связанную staff-role, сбрасывает
overrides, пишет audit/outbox и инвалидирует доступ. Прямой запрос Manager или
попытка Director назначить Director/system_admin отклоняются независимо от UI.
