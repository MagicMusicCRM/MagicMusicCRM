# UAT-003 — единый ID-ledger и каталог evidence

Статус: **PARTIAL**. Канонический формат и журнал уже известных production-ID
созданы; полный набор фактов появится только после повторного owner mega-UAT.

## Закрытый локальный разрыв

Раньше UUID находились в нескольких абзацах `README.md` и двух отдельных API
JSON. Это не позволяло машинно проверить полноту фактов и быстро отличить
отсутствующий ID от намеренно скрытого значения.

Теперь единственный машиночитаемый журнал находится в
[`api/uat-id-ledger-20260812.json`](api/uat-id-ledger-20260812.json). Каждая
запись содержит UAT-сценарий, тип объекта/факта, UUID, версию или counts при
наличии, бизнес-результат и ссылку на evidence. Известные branch, ingestion,
Lead, outbox, Lesson и Task ID собраны без дублирования.

Privacy-блок журнала явно фиксирует:

- секреты, bearer/cookie/session values не сохраняются;
- телефоны и email не сохраняются;
- UUID, версии, counts, суммы и бизнес-результаты не маскируются.

`missingRequiredClasses` является проверяемым остатком, а не скрытым текстом:
туда входят room/teacher/staff/link/group/family/commerce/Lesson-fact и
data-quality ID, которых нет в старых production-доказательствах.

## Правило для оставшегося owner-UAT

После каждого успешного commit сначала добавляются aggregate ID, version,
audit/outbox/idempotency и созданные fact ID в ledger, затем UI/API/DB evidence
ссылается на эту запись. Raw trace до публикации проверяется на `password`,
`secret`, `token`, `authorization`, `cookie`, телефон и email. Денежные значения
и предметные результаты остаются открытыми.

## Остаток до PASS

Во время актуального production owner-прохода необходимо заполнить все классы
из `missingRequiredClasses`, удалить этот массив только после reconciliation и
проверить, что каждый созданный UAT-объект имеет один ledger record и хотя бы
одну evidence-ссылку. Production в этой волне не изменялся.
