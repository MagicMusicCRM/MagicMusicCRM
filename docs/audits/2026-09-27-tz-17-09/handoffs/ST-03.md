## Воспроизведение и evidence

Предусловия: собственный PostgreSQL 17 cluster на loopback с ролью `magiccrm_app`; Windows Flutter toolchain и локальный NestJS. `HTTP_JOURNEY_ADMIN_URL`/`TEST_POSTGRES_ADMIN_URL` должны вести **только** в maintenance DB собственного loopback cluster. Каждый runner режим запускать последовательно: он создаёт, мигрирует и удаляет свою БД. Реальные платёжные провайдеры, push/SMTP и production не подключать. UI тесты используют API login и memory token/workspace store в Windows Debug.

```powershell
$env:HTTP_JOURNEY_ADMIN_URL = '<URL собственной loopback maintenance DB /postgres>'
node scripts/http-journey-check.cjs --audit-installment-cycle
node scripts/http-journey-check.cjs --audit-partial-purchase
node scripts/http-journey-check.cjs --audit-purchase-retry
node scripts/http-journey-check.cjs --audit-finance-access
$env:TEST_POSTGRES_ADMIN_URL = $env:HTTP_JOURNEY_ADMIN_URL
Push-Location server
node test-tools/run-tests.cjs --runTestsByPath src/crm/commerce/subscription-issue-postgres.integration.spec.ts
Pop-Location
```
