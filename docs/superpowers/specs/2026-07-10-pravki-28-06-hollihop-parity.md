## Решения заказчика (зафиксированы 2026-07-10)

1. **Период данных.** Данных раньше марта 2023 не существует — HolliHop до этого не использовался. Требование «с 2020» закрывается полной выгрузкой всего, что есть (2023-03 → 2027).
2. **Правила списания** по статусам занятий — адаптировать из HolliHop «чтобы всё было логично» (драфт ниже, финальное утверждение на демо).
3. **Роль «Директор»** — новая роль. Иерархия: `client < teacher < admin < manager < director < system_admin`. **Управляющий (manager) теряет доступ к общешкольным финансам и связанной аналитике**; финансы в карточках клиентов (история оплат, баланс) остаются видны. ⚠️ Это меняет бизнес-правило из AGENTS.md («Управляющий — полный доступ») — AGENTS.md обновить.
4. **Задачи/комментарии/логи из HolliHop** — если API не отдаёт (методов нет в API 2.0), заказчик/владелец делает ручной Excel-экспорт из UI и передаёт файлы. Импортер `server/src/migration/import-hollihop-exports.ts` уже существует.
5. **Многооконность.** По прямому запросу директора школы UX должен быть близок к HolliHop. Пункт P2.2 gap-отчёта («не клонировать многооконность») **отменяется точечно**: там, где многооконность/знакомые паттерны HolliHop сохраняют привычный UX — разрешены. Стилистика остаётся наша (токены v7), паттерны — из HolliHop.

## Драфт правил списания и начисления ЗП по статусам занятия (п. б — утвердить на демо)

| Статус занятия | Списание с абонемента клиента | Начисление педагогу |
|---|---|---|
| Занятие (проведено) | 100% (duration/60 астр.ч.) | ставка × часы |
| Неоплачиваемый пропуск | 0 — час сохраняется на абонементе | 0 |
| Бесплатное занятие | 0 | ставка × часы (за счёт школы) |
| Оплачиваемый пропуск | 100% — час сгорает (поздняя отмена и т.п.) | ставка × часы |
| Частично оплачиваемое занятие | доля K (настраивается при простановке статуса, напр. 50%) | ставка × часы × K (по умолчанию; настраиваемо) |

Дополнительно: пробный урок, после которого клиент не купил абонемент, — в конце месяца в отчёте «Статистика преподавателей» админ вручную ставит уч. единице «входит в оклад» (0 руб) — как в HolliHop (image9→image10). Заметки к занятию обязательны для всех «нестандартных» статусов (textarea в модалке, image5).

## Сводка: требования ↔ текущее состояние

### 1. Карточка Лида — в основном готова
- Есть: ФИО/статус/филиал/уровень/источник/дата обращения, прикрепление к ученику, задачи, история (3 слоя).
- Частично: возраст (birthday есть, «N лет» не вычисляется), одно контактное лицо (нужен список agents), категория — text вместо select, одна дисциплина (нужен multi-select), кнопка пробного только на доске.
- Нет: сущность «заявка лида» (только текст `applicationData`). Источник данных: `GetStudyRequests` из API.

### 2. Карточка Ученика — бекенд опережает UI
- Есть: lifetime value, задачи+история, домашка (несрочное — уже готово!), семьи.
- Частично: конверсия копирует не все поля; **teacher_note/admin_comment — бекенд готов (RBAC, миграция 0037), в UI нет переключателя типа**; личный счёт — вычисляемый баланс без ledger.
- Нет: списание с абонемента другого члена семьи (`reconcileSubscriptionUsage` жёстко по `student_id`); чёрный список без поведения; audit-лог не выведен в карточку.

### 3. Расписание и статусы занятий
- Есть: drag&drop разовый перенос (PATCH одного занятия, оптимистично).
- Нет: **модель постоянного расписания** (занятия — разово материализованные строки до 2028-01-01, шаблонов/серий/override нет); **5 статусов посещения** (сейчас бинарно present/absent); связь статуса со списанием и ЗП.
- UI-пробелы карточки: аудитория в строке занятия, остаток абонемента в админ-карточке, лента дат-квадратиков.

### 4. Ставки и зарплата педагогов — с нуля (самый большой блок)
Нет ничего: ни ставок (`app.teachers` без rate), ни ставки на группе (`groups.price_per_lesson` — клиентская цена), ни начислений/выплат/задолженности, ни отчёта. Карточка педагога: нет редактирования даты рождения/уровней/категорий/филиалов (только HolliHop-импорт в custom_data), нет даты начала работы, нет мультивыбора дисциплин (`teacher_disciplines` отсутствует). Запрета «урок с чужой дисциплиной» у нас и нет — требование выполняется само.

### 5. Уведомления
Инфраструктура (FCM+очередь+воркер) готова. Нет: триггера на нового лида/задачу, планировщика напоминаний по `due_at` (образец — lesson reminders), **вебхука заявок с сайта**, кастомного звука, звука на Windows-десктопе (FCM там не работает — нужен WebSocket+local_notifier, как в мессенджере).

### 6. Выгрузка HolliHop
- Дамп от 2026-06-22, 11 сущностей; `HOLLIHOP_AUTH_KEY` настроен; импортер идемпотентный, dry-run.
- Перегнать `GetEdUnits` с `dateFrom=2023-01-01` (сейчас 2024-01-01 — потерян 2023 год занятий).
- Довыгрузить из API 2.0 (https://hollipedia.t8s.ru/books/api/page/api-20): GetStudyRequests, GetBalances, GetIncomesAndOutgoes, GetEdUnitLeads, GetLessonPlans, GetEmployees (перепроверить), GetCompanies, GetClientFiles, GetClientStatuses, GetEmployeeStatuses, GetPrices, GetDiscounts, GetSurcharges, GetLevels, GetLearningTypes, GetEntranceTests, GetOfflineTestTypes, GetPersonalTestResults, GetEdUnitTestResults, GetOnlineTestResults, GetEdUnitStudentReports, GetSupplies, GetEdMaterials, GetAnnouncements.
- GetTasks/GetComments/GetStudentLogs/GetLeadLogs **в API 2.0 не существуют** — потому дамп-скрипт их «терял» молча. Источник: ручной Excel-экспорт от владельца → `import-hollihop-exports.ts`.
- Лимиты API: 600 запросов/30 сек; `take` ≤ 10 000. Read-only: используем только `Get*`.
- Финальная перегонка — непосредственно перед отключением школы от HolliHop.

## Порядок работ (эпик в Linear)

1. Перевыгрузка HolliHop (все Get-методы, dateFrom=2023-01-01, лог ошибок по эндпоинтам).
2. Быстрые UI-победы (бекенд готов): возраст, переключатель типа комментария, кнопка пробного в карточке, дата обращения, исполнитель задачи, аудитория, абонементы в админ-карточке.
3. Новые импортеры: заявки, ledger, пробные лидов, домашка, цены/скидки; Excel задач/комментариев.
4. Модель расписания: серии + генератор + override-переносы + 5 статусов + правила списания + UI-паттерны (лента дат, tooltip, модалка).
5. Зарплатный модуль: ставки → начисления → выплаты/задолженность → отчёт «Статистика преподавателей».
6. RBAC: роль director, срез финансов у manager.
7. Уведомления: вебхук, триггеры, планировщик задач, звук (вкл. Windows).
