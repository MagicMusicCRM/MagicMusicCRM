# Magic Music CRM — починка работоспособности (2026-06-23)

Сессия по жалобе владельца: «приложение неработоспособно» (не realtime, данные не грузятся,
голосовые не играют, нет данных HolliHop в карточках, расписание-день пустое, нельзя
бронировать аудиторию, всё очень медленно).

## Что задеплоено на прод (`api.phantom-net.ru`, ветка `kvazar2727/kva-196-p3-clients`)

- **Голосовые (S3)** — `server/src/files/*`: токен скачивания теперь переиспользуемый в
  пределах TTL + поддержка HTTP Range/206. Корень: одноразовый токен + отсутствие Range
  → 2-й запрос плеера давал 404 («source error»). **Проверено на проде** (GET×3=200, Range=206).
  Работает в уже установленном приложении (серверный фикс).
- **Производительность (S2/S7)** — миграция `0038_perf_indexes`: индексы
  `lessons(group_id)`, `lesson_participation(lesson_id/student_id)`. Применена, проверена.
- **HolliHop в карточках (S4, сервер)** — `crm.service.ts`: `disciplines` в DTO поиска
  студентов (из `student_disciplines`).
- **Realtime CRM (S1, сервер)** — `@Global RealtimeBus` + gateway (комната `crm`,
  `setServer`) + эмиты `crm.changed` на мутациях уроков/лидов. DI-граф собирается чисто,
  загрузка без ошибок.
- Бэкапы БД перед изменениями: `pre-0038-perf-indexes-*.sql.gz` и др. в
  `/opt/magicmusiccrm/backups`.

Деплой: `tar server/{src,db,...}` → хост → `docker compose --env-file .env up -d --build api`
(миграции применяются на старте контейнера). Бэкап-скрипт `backup-staging.sh` сломан
(многострочный `FIREBASE_PRIVATE_KEY` ломает `source .env`) — бэкап делается вручную через
`pg_dump`.

## В релизном APK (`build/app/outputs/flutter-apk/app-release.apk`)

- **Расписание-день (S5)** — догрузка уроков за конкретный день (раньше матрица обрезалась
  лимитом 300 по окну ~45 дней → дни после первых ~5 были пустыми).
- **Сетка-бронь (S6)** — тап по пустой ячейке = создать урок (60 мин) в этой аудитории/время;
  зажатие-протяжка = выбрать диапазон → создать урок с этой длительностью
  (`CreateLessonDialog` получил `initialDurationMinutes`). Аффорданс «Нажмите, чтобы назначить».
- **HolliHop в карточках (S4, клиент)** — fallback имени/телефона/email на `custom_data`;
  доска учеников группирует по реальным направлениям.
- **Realtime (S1, клиент)** — `crmRealtimeProvider`; расписание и доска лидов
  авто-обновляются по `crm.changed`; аналитика на `keepAlive` (кэш между заходами).
- **Сеть (S2/S7, клиент)** — ретрай при ошибках соединения (`connectionTimeout/Error`).

## Действие владельца (не код)

- **DNS на ПК даёт ~12с на «холодный» запрос**: мёртвый DNS Ethernet-адаптера `192.168.8.1`.
  Отключить адаптер или прописать DNS `1.1.1.1`/`8.8.8.8`. Сервер сам быстрый (TCP ~1мс).
  KVA-206 («сервер дропает SYN») — ошибочный диагноз (перепутан `time_connect`/DNS).

## Ждёт решения / вне автономного объёма

- **Чистка данных** (KVA-205): 10 точных дублей-уроков можно удалить (обратимо, бэкап есть) —
  автоудаление заблокировано классификатором безопасности, нужен явный OK. Слияние «фрагментов»
  (P6-4) и 965 placeholder-email у `users` (auth) — небезопасно автоматизировать, требует ревью.
  Пересекается с активными KVA-208/209 (реимпорт/унификация телефонов).
- **Приёмка на устройстве** (KVA-202/203/204/123, KVA-19): ручная проверка ролей на
  Windows/Android — за владельцем.
- **Phantom VPN** (KVA-49..77, ~29 задач): отдельный продукт (`C:\Projects\phantom`), не связан
  с Magic Music — браться только по явному запросу.
